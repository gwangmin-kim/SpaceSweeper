### 🎯 목표

### ✅ 진행 상황

- [x] `UpgradeDefinition`: 업그레이드에 대한 모든 정보를 담고 있는 ScriptableObject 클래스. 고유한 id, 업그레이드 이름, 설명, 비용, 슬롯 아이콘, 부모(선행 해금 조건으로써 작용)를 가지고 있으며, 후술할 `UpgradeEffect`를 가지고 있다. 업그레이드 트리의 각 슬롯은 자기 자신의 업그레이드 내용에 대한 `UpgradeDefinition`을 가지고 있다.
- [x] `UpgradeEffect`: 업그레이드를 적용할 때 실제 로직을 담고 있는, ScriptableObject 추상 클래스. `UpgradeEffect`를 상속받는 모든 SO는 업그레이드 내용을 실제 게임에 반영하는 `Apply` 함수를 구현해야 한다. 현재 플레이어의 스펙에 영향을 주는 `StatUpgradeEffect`와 무기 스펙에 영향을 주는 `WeaponUpgradeEffect`가 구현되어 있다.
- [x] 업그레이드 트리 구현: 각 슬롯은 정방형 버튼으로 되어있으며, 각 버튼은 자신의 부모 노드가 구매되어야만 가시화 및 버튼 활성화가 이루어진다. 버튼에 마우스를 올리면 마우스 위치에 해당 업그레이드 정보를 툴팁으로써 보여준다. 버튼을 누르면 재화를 소모해 구매를 시도하며, 구매가 이루어지면 `UpgradeDefinition.effect.Apply` 함수를 호출하여 업그레이드 내용을 반영하고, 해당 업그레이드 id를 `GameData` 객체에 추가한 뒤 `SaveGame` 함수를 호출하여 저장한다.

### 🚀 트러블 슈팅

**문제 상황:**
자료 구조 형태를 대거 수정하고, 영구 유지되는 싱글톤 매니저와 특정 씬에서만 존재하는 싱글톤 매니저 간의 참조가 얽힘. UI 컨트롤러는 UI 오브젝트에 달아두었더니, 해당 오브젝트가 비활성화 될 경우 제대로 동작하지 않는 문제가 있음.

**시도한 방법:**
1. 매니저에 접근할 때는 반드시 .Instance를 사용하여 접근하도록 코드 수정. 매니저가 달린 오브젝트는 activeSelf = false가 되는 경우가 없도록 변경
2. UI 요소의 경우, 활성화/비활성화가 필요한 경우 컨트롤러는 Empty object에 달아두고, 해당 오브젝트의 자식 오브젝트로 실제 UI 요소를 달아두어 컨트롤러가 자기 자신을 직접 on/off하지 않고 자식 오브젝트를 참조하여 외부에서 제어하도록 변경

**해결:**
변경 후 현재로서는 버그가 발견되지 않음.
